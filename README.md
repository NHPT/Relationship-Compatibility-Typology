# RCT 关系适配类型学

Relationship Compatibility Typology

RCT 通过日常场景选择，梳理你的生活目标、相处习惯与决策偏好，生成个人类型画像，帮助你了解与不同类型相处时的共同点、差异和需要协商的问题。

当前为探索原型。题目和类型规则尚未经过真实样本验证，结果反映本次回答对应的设计分类，不能直接证明两个人的关系质量、合作成效或关系能持续多久。

## 类型体系（8 型 + 附加观察标记）

三条主轴的倾向组合形成 8 个基础型；冲突、边界维度另设 E/F 观察标记，不覆盖基础类型。它们是设计分类，不是已被实证确认的自然人群类别。

**三主轴**：

| 主轴 | 两极 |
|---|---|
| X 人生主轴 | 安稳守成 ↔ 进取攀登 |
| Y 关系形态 | 深度共生 ↔ 独立并置 |
| M 金钱模式 | 规划积累 ↔ 即时体验 |

**8 型完整定义**：

| 家族 | 规划积累 | 即时体验 |
|---|---|---|
| A 安稳共栖 | A1 安稳共栖·稳重型 | A2 安稳共栖·温情型 |
| B 安稳自在 | B1 安稳自在·克制型 | B2 安稳自在·随性型 |
| C 并肩进取 | C1 并肩进取·务实型 | C2 并肩进取·激情型 |
| D 自由追梦 | D1 自由追梦·理性型 | D2 自由追梦·洒脱型 |

- **E 冲突回避倾向**：部分回答偏向推迟或回避分歧，需要结合实际处理和修复过程理解。
- **F 边界待澄清**：部分回答涉及不同的交往或家庭决策边界，需要进一步沟通。
- **SWING 倾向未明确**：本次回答没有满足现有类型阈值，不代表人格不稳定或在隐瞒。

## 如何使用

1. 点击「开始测试」，完成 20 道题，每题保留 4 个选项和 60 秒阅读提示；提示结束后仍可作答。
2. 按自己通常会怎样处理来选择，结合结果页的个人倾向和类型适配参考思考实际相处。
3. 如需重测，保持相近的作答对象和生活情境。结果一致只说明分类重复性，不等于分类准确；结果变化也不能作为说谎判断。

目前每个维度由多道题综合计分，但随机题目是否等价、选项是否有足够区分度，仍需逐题审查和真实样本研究。更换题面与打乱选项只能减少机械重复，不能防止迎合答案。

## 场景与结果边界

婚恋伴侣、搭伙创业、长期伙伴和团队协作需要不同的情境信息。当前使用同一套单人题库，包含婚育与家庭题，尚未实现四套场景专属评估；类型建议不能代替各场景的实际验证。

- 婚恋：还需要双方确认婚育、定居、金钱安排和实际边界。
- 创业：还需要验证能力、责任、出资、决策、利益分配及退出规则。
- 朋友：还需要观察互惠、尊重、支持方式与交往节奏。
- 团队：还需要结合岗位职责、能力、交付表现及组织约束。

单人类型无法确定尚未作答的另一个人的倾向，也不能直接得出两人的适配结论。结果页按三条主轴的已明确方向列出「三轴同向」「差异协商」「三轴差异」，逐个说明共同点与协商重点；主轴未明确时标注待确认，不按缺失倾向强行排名。这是偏好比较参考，尚未建立预测关系质量的推荐模型。

## 研究反馈

结果页的可选反馈和历史导出仅提供本地记录，不会上传至 GitHub 或其他服务器，保存反馈不会自动改变计分或推荐。新结果保存逐题答案、题面、选项、分数、随机结果标识与测评版本；历史旧记录不补造这些信息。当前仍缺少独立参与者、关系与随访标识，不足以完成正式校准。

当前没有真实样本效度结果；代码测试输入只能检查程序行为，不能证明测评准确。GitHub Pages 提供静态页面托管，不是反馈接收后端；自动汇总需要另行部署接口、数据库和明确的研究流程。

## 当前题库覆盖

32 个模板，每次按固定配额抽取 20 题；随机题面和选项不代表等价试卷已经验证。

| 内容 | 模板数 | 每次题数 | 结果用途 |
|---|---:|---:|---|
| 人生主轴（目标取向） | 5 | 3 | 八型主轴 X |
| 关系形态（共同参与与独立空间） | 5 | 3 | 八型主轴 Y |
| 冲突模式 | 5 | 3 | 附加观察标记 C |
| 边界模式（交往、父母决策混合） | 6 | 4 | 附加观察标记 B |
| 消费与金钱偏好 | 5 | 3 | 八型主轴 M |
| 生育意愿 | 3 | 2 | 独立标签 K |
| 定居倾向 | 3 | 2 | 独立标签 S |

这七项是当前设计的测量内容，不代表各项已经验证有效。尚未完整测量承诺与信任、支持与互惠、合作责任、能力、利益分配和退出机制。交往边界与家庭决策混合、不同财务情境的计分等问题仍需逐题重设计。

## 开发与部署

HTML、CSS 和原生 JavaScript 静态页面，无后端或构建步骤。测试记录保存在当前浏览器的 `localStorage`，不会自动汇总至服务器。

## 本地运行

```bash
cd Relationship-Compatibility-Typology
python3 -m http.server 8090
# 打开 http://localhost:8090
```

## 部署到 GitHub Pages

1. 在 GitHub 新建仓库。
2. 推送本项目：

```bash
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/<用户名>/Relationship-Compatibility-Typology.git
git push -u origin main
```

3. 仓库 **Settings → Pages → Branch 选 `main`（根目录）→ Save**。

## 使用边界

- 区分「答案」「类型归纳」「适配建议」「真实关系表现」四层，不能互相替代。
- 人生取向、独立程度或消费偏好不能推导出忠诚、情绪稳定、生育意愿或工作能力。
- 结合长期行为和具体约定理解结果，不用类型评判人品，也不把 E/F 当成一票否决。
