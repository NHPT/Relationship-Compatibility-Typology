# RCT 关系适配类型学

Relationship Compatibility Typology

你希望怎样相处，又通常怎样回应别人？RCT 从婚恋、朋友、创业和团队场景梳理相处风格与具体期待；另设“人生与人性探索”，覆盖人生、世界、价值、家庭、婚姻、欲望、忠诚和道德选择等 48 项内容。

这是探索原型。题库、分数和类型规则尚待真人认知访谈与独立样本验证；结果反映本次回答，不能直接证明关系质量、长期结局或工作能力。

在线使用：[RCT](https://nhpt.github.io/Relationship-Compatibility-Typology/)

## 1. 关系测评：四个独立入口

每个入口有独立的 32 道固定场景题、三条风格轴、类型名称、具体条件和结果解释。各入口均为单人作答，代码和记录带场景标识，不把某场景结果迁移到另一场景。

| 入口 | 三条风格轴 | 单独记录的七项条件 |
|---|---|---|
| 婚恋伴侣 | 生活节奏、陪伴方式、开支取向 | 生育、居住、家庭决定、财务、交往约定、照护、关系计划 |
| 朋友相处 | 活动取向、联系节奏、聚会开支 | 回复约定、借款、隐私、支持期待、玩笑、费用、距离变化 |
| 创业合伙 | 经营节奏、协作方式、资源投入 | 主要投入、亏损上限、决定权限、收益、退出、资料成果、参与时间 |
| 团队协作 | 任务节奏、协作接口、资源安排 | 当前角色、反馈、响应窗口、决定权限、验收、升级、任务变更 |

父母参与决定属于婚恋条件，不参与“约定与透明”的行为分。非婚恋入口没有婚育题。创业和团队题记录合作安排与自报做法，不能替代能力、资产、交付或权限核验。

## 2. 人生与人性探索：48 项内容

这是独立题库和结果入口，不参与关系类型计算。48 项主题分为八组，每组六项，共 243 道原生中文题。各细项至少一题，其中世界观、道德困境、心理防御相关内容各六题，其余主题各五题。完整对应表见 [48 项内容覆盖表](RCT-48项内容覆盖.md)。

| 分组入口 | 覆盖内容 | 题数 |
|---|---|---:|
| 安全、欲望与亲密 | 自我保护、物质、控制、性与繁衍、恐惧、欲望管理 | 30 |
| 情感与重要关系 | 依恋、嫉妒、愤怒、爱情婚姻、家庭亲情、友情 | 30 |
| 自我认识与判断 | 自我认知、自尊、理性、认知开放、真实、自我辩解 | 31 |
| 人生与价值取舍 | 人生观、世界观、价值观、金钱成功、信仰、生命态度 | 31 |
| 诚信、公平与原则 | 诚信、忠诚责任、善意、公平、利他、利益与原则 | 30 |
| 欲望与道德困境 | 知足、权力使用、自律、两难、宽恕、操纵 | 31 |
| 担当与群体压力 | 群体认同、勇气、逆境、责任、从众、关怀 | 30 |
| 成长、合作与创造 | 谦逊、探索、审美、独处、合作、改变 | 30 |

1. 选择一个分组开始，不必一次做完。
2. 按通常做法或目前想法选择，点击“下一题”继续。点击选项后自动保存草稿。
3. 不适用、不想回答或没有合适选项时，可跳过；结果区分已答、跳过和未答。
4. 返回主题页后，可续答未完成的分组，或回看已完成分组。
5. 完成一组可看六项结果；随时可查看 48 项总览。每项保留题目、实际选择和反思提示。
6. 可以从结果回到对应主题修改当前草稿。已保存的报告不被修改；重复查看相同范围和回答不重复新增报告。

“48 项”表示内容覆盖，不代表 48 个已经验证、相互独立的心理维度。重叠内容使用不同情境，例如希望获得决定权与拥有权力后的做法、产生愤怒与后续追责、欲望满足与欲望升级。交叉主题的选项不合成道德总分。

这部分输出描述性回答梳理，不生成忠诚度、人品分、善恶等级、心理疾病诊断或行为预测。安全求助不等于胆小，边界不等于自私，原谅不要求放弃追责，信仰和婚育选择没有统一高低排序。选项仍可能受社会期许、自我认识和情境假设影响。

## 3. 关系题量与使用

四套共 128 道题，每次完整作答所选场景的 32 题：

| 内容 | 本次题数 | 输出 |
|---|---:|---|
| 三条场景风格轴 | 3 × 3 = 9 | 方向条、选择次数、场景风格 |
| 八项行为内容 | 8 × 2 = 16 | 回答分布雷达图、逐题证据、沟通行动 |
| 七项具体条件 | 7 | 原意愿或安排与协商事项，不计分 |

八项行为内容是需求表达、支持回应、分歧修复、约定与透明、承诺履行、互惠分担、共同决策、压力应对。各场景使用对应情境，不通过替换“伴侣/同事”随机生成题面。

1. 选择本次要了解的场景，保持同一作答对象。
2. 选择自己通常采用的做法，再按“下一题”确认。可改选，可返回前题修改。
3. 每题 60 秒仅作阅读提示。到时不自动选择、不自动跳题，也不把未答当中性分。
4. 查看风格、行为和具体条件，再与对方核对实际情况。

每套题固定覆盖，只有选项位置随机；标识、语义和分值不随位置变化。32 题是内容覆盖的试测起点，并无证据证明它是最佳题量。选项仍可能受社会期许影响，不能防止迎合答案。

## 4. 关系结果规则

### 4.1 风格方向与类型

每条风格轴三题，选项按方向计 -2、-1、+1、+2，合计范围 -6 至 +6。合计 ≤-2 为左侧取向，≥+2 为右侧取向，-1 至 +1 保留为情境取舍。阈值是人工设计规则，不是准确性置信度。

三轴均呈现方向时，每个场景有八个组合原型，分别使用 L、F、V、T 前缀。不同入口的同号类型没有跨场景等价含义。类型配有固定颜色、几何符号、代码与文字，理解不依赖颜色。

一条或多条轴靠近中点时，生成本场景的“情境弹性型”，仍保留另外的方向、三条连续位置、两侧选择次数、行为回答与全部具体条件。它描述不同题里采用两侧做法的结果，不推断适应能力。新测评不再生成 SWING 或“倾向未明确”的空白兜底结果。

旧版只要任一主轴未过阈值就退回 SWING，是此前整体画像丢失的直接原因。旧记录保留原名称，不用新规则改写。

### 4.2 行为观察与图形

每项行为两题，选项按题面中主动说明、协商、跟进的行动计 3、2、1、0 分，合计 0–6。雷达图按各项满分归一化，逐项保留题目和实际回答；分数不表示能力、在人群中的排名或适配概率，图形面积没有综合意义。

两题合计 5–6 显示“选择中较明确”，2–4 显示“两题做法有差异”，0–1 显示“较少主动跟进”。低分仅产生具体观察提醒，不覆盖风格类型，也不成为对所有关系的一票否决。暂停后约定重返沟通属于明确修复做法，不被当作回避。

### 4.3 具体条件与适配参考

七项条件保留实际选项，不加到风格或行为分。条件中的“未决定”“视情况”是独立且可解释的信息，不代表拒绝或同意。

结果首先列出值得核对的实际相处做法与场景约定，再列本场景八种风格的共同点和协商差异。中点轴按情境讨论，全部中点也保留完整候选参考，不随机强分类型。偏好同向不保证适配，差异也不必然冲突；没有“高兼容”、准确率或关系结局概率。

## 5. 数据、反馈与历史

没有后端。研究反馈、测评与历史只保存在当前浏览器的 `localStorage`，不会上传 GitHub 或其他服务器，不会自动训练或校准。GitHub Pages 只托管静态页面。

新结果记录场景、规则版本、题序、题面、稳定选项标识、实际回答、分值及结果标识。研究反馈绑定本次结果，使用相同场景；时长和状态必须主动选择，对方风格未知可留空，同一次反馈保存会更新原记录。

历史按场景显示。同场景且同规则的新记录可以查看分类重复情况，但仍需保持同一作答人、对象和相近情境；当前没有可靠的参与者标识。不同场景或旧规则不合并评估稳定性。旧记录原样保留，不补造答案或版本。

支持导出本次关系画像 JSON、全部本地记录 JSON、研究反馈 CSV，以及探索草稿与探索报告 JSON。浏览器存储失败会明确提示，当前内存回答和报告仍可导出。关系历史、反馈和探索使用独立存储；清空探索不影响关系记录，清空关系历史不清空探索和已保存反馈。

关系题库于本次完成 128 题中文改写，版本提升为 `rct-scenes-2026-11-23-v3`。题干不超过 45 字，选项不超过 32 字；保留方向和选项分值映射，但部分复合行动已精简。旧版记录仍保留，不与新版合并统计。长度检查是编辑约束，不能代替真人阅读测试。

探索使用 `rct-exploration-2026-11-23-v1`。版本不匹配的草稿不能覆盖或续答，须先导出并清空。未知选项不当成已答，损坏的报告不进入展示列表。

正式校准还需要明确预测目标、参与者与关系标识、独立双方结果、随访与结局标准、去重及开发/验证样本分离。代码测试数据不计入真人研究样本。

## 6. 开发与验证

HTML、CSS 与原生 JavaScript，无构建步骤。GitHub Pages 从 `main` 根目录部署。

```bash
python3 -m http.server 8090
node --test tests/contracts.cjs tests/exploration-contracts.cjs
```

浏览器回归使用 Playwright 和本机安装的 Chrome：

```bash
npm install --no-save playwright
node tests/browser.cjs
node tests/exploration-browser.cjs
# 通过 RCT_URL 环境变量可验证部署站点。
```

浏览器回归覆盖鼠标、触屏、键盘、四场景完整作答、情境弹性结果、返回改选、超时、本地反馈、JSON/CSV 导出、重载与历史隔离、旧版数据、存储失败，以及 320/375 像素布局。探索回归覆盖八组完整答题、48 项总览、跳过、续答、修改、报告快照、导出、数据隔离与保存失败。证据默认保存在 Git 忽略的验证目录，可用 `RCT_ARTIFACT_DIR` 指定输出位置。

程序回归通过只证明实现符合当前规则，不能证明题库内容效度、重测信度或关系预测效度。后续重点是认知访谈、选项区分度、作答负担与分场景独立验证。
