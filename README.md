# RCT 关系适配类型学

Relationship Compatibility Typology

RCT 提供个人测评和婚恋测评两个单人入口，按“个人基础画像＋婚恋专项模式＋独立条件标签”组织。个人主型说明通常怎样安排自己的生活；婚恋模式说明怎样回应、联系、处理分歧和共同安排。日常交往与合作可使用个人报告的相处参考，合作能力与交付仍需实际核验。

本版是探索原型。数量来自选取的分类方向，尚无人群效度或关系结果预测验证；规则检查通过不等于心理测量已经有效。

在线站点：[RCT](https://nhpt.github.io/Relationship-Compatibility-Typology/)。本地预览：`http://localhost:8090/`。

## 1. 内容结构

| 入口 | 内容 | 输出 |
|---|---|---|
| 个人测评 | 48 项主题、八组，保留原 243 题并追加 12 道中性方向题，共 255 题 | 8 种个人主型、三个方向、原有特征、情境选择与逐题依据 |
| 婚恋测评 | 12 道模式题、9 道生活方式题、16 道行为题、7 道条件题，共 44 题 | 个人基础快照、16 种关系模式、生活方式、行动观察与条件标签 |

两个入口不包含多人比较。婚恋模式由婚恋专项回答独立生成，没有个人 P 类型到婚恋 L 模式的自动换算。朋友、创业、团队的旧场景仅保留为历史定义，页面不加载对应题库。

## 2. 个人主型：生活取向

本次保留当前 8 种生活取向主型，不机械回退到原 14 个关注点类型。三个方向只说明条件相近时的生活组织偏好，不代表完整人格。原 14 型包含可同时出现的求证、原则、共情、责任等关注点，直接用支持比例选出一个人格主型缺乏充分依据；这也不能反过来证明当前 8 型已经有效。48 项主题中的回答、特征与情境差异继续独立保留，真人验证后仍可修订规则。

| 方向 | 一侧 | 另一侧 |
|---|---|---|
| 变化方向 D | 巩固已有安排 | 尝试新的方向 |
| 参与方式 W | 独立推进 | 协同推进 |
| 价值取舍 V | 现实可行优先 | 内在意义优先 |

新增题在安全和基本责任得到保障、条件相近的情况下比较偏好。协同不等于服从，现实不等于只认钱，意义不等于忽略现实。一个题目只观察一个方向；旧题中的共情、责任、守约不直接用作互斥类型。

| P05 | 开路自航型 | 尝试 | 独立 | 现实 | 赤狐 |

每个方向观察四题，选项前两项归左侧、后两项归右侧。至少三题有效才达到最低覆盖；至少三题选择同侧且超过另一侧，才确定方向。三个方向均明确才生成唯一主型。覆盖不足或两侧各半保留方向与可能组合，候选范围不当成已测出的主型或辅助型；分组报告不宣布全局主型。

原有八条特征仍按各自四个指定情境解释：至少三题采用相应做法时归纳为重复特征，四题中两题采用时保留情境差异。其他选择、跳过和未答保留原状，不统一归入相反特征，不生成道德总分、忠诚度或行为概率。

相处参考按三个明确方向的同向与不同向说明协调事项，展示自己的回答依据。它不证明对方类型或未来关系结果。动物仅是识别符号，不参与计分，也不从动物习性解释人格。

各组可续答、跳过和修改，点击选项后自动保存草稿。原主题与旧题标识不重排，新增观察题分散到现有主题末尾。48 项表示内容覆盖，不代表 48 个独立心理量表。

## 3. 婚恋模式

| 方向 | 一侧 | 另一侧 |
|---|---|---|
| 回应起点 R | 先理解感受 | 先处理安排 |
| 联系节奏 S | 密切联系 | 保留空间 |
| 分歧节奏 C | 当下讨论 | 暂停后复谈 |
| 共同安排 J | 共同参与 | 分工自主 |

两侧均要求尊重暂停请求与已有约定。先处理安排不等于缺少共情，暂停不等于冷处理，分工不等于单方决定重大事项。

名称采用“回应与分歧模式＋联系与安排方式”。主标题显示前一层，副标题显示后一层，保存与导出使用完整名称和唯一代码。

| 回应与分歧 | 常伴共议 | 常伴分工 | 自在共议 | 自在分工 |
|---|---|---|---|---|
| 共感直谈 | L01 | L02 | L05 | L06 |
| 共感缓谈 | L03 | L04 | L07 | L08 |
| 共策直谈 | L09 | L10 | L13 | L14 |
| 共策缓谈 | L11 | L12 | L15 | L16 |

例如 L01 的完整名称为“共感直谈·常伴共议模式”，L16 为“共策缓谈·自在分工模式”。共感/共策表示先回应感受/先回应安排；直谈/缓谈表示当下谈/暂停后按约复谈；常伴/自在表示密切联系/更多空间；共议/分工表示日常共同参与/分工自主。

每个方向三题，选项记 -2、-1、+1、+2，合计 ≤-2 为左侧，≥+2 为右侧，-1 至 +1 保留情境取舍。四个方向明确才落入十六种固定模式。所有 81 种方向及中点组合保留已知方向，中点组合不增列为固定模式，也不推断适应能力。

生活节奏、陪伴方式、开支取向另行显示。八项行动观察仍为需求表达、支持回应、分歧修复、约定与透明、承诺履行、互惠分担、共同决策、压力应对。各项两题按主动说明、协商、跟进记 3、2、1、0 分：合计 5–6 为选择中较明确，2–4 为部分说明与跟进，0–1 为较少主动跟进。雷达图只展示本次回答，面积没有综合意义。

生育、居住、家庭参与、财务、交往约定、照护和关系计划各自保留，未决定或附条件不能当作同意或拒绝。生活方式、行为和条件均不能改变婚恋模式。

婚恋相处参考使用四个模式方向。全部明确轴同向的模式归入“更容易形成默契”，全部明确轴反向的模式归入“需要更多磨合”；中点不参与排列。每项给出依据、限制和沟通事项；同向不保证关系结果，差异不等于冲突。

每次测评固定覆盖 44 题，仅选项位置随机。必须选择并点击下一题，可返回修改；60 秒仅作阅读提示，不自动作答或跳题。分值与题面由题库重取，不相信答案附带的合计或文本。

## 4. 基础画像、历史与导出

婚恋报告生成时读取当前个人草稿，将个人主型、方向、特征与依据保存为基础快照，附来源和版本。不足时标明个人主型尚未确定；婚恋报告仍可独立生成。后续修改个人草稿不改变已保存婚恋报告。

数据仅在当前浏览器的 `localStorage`，无后端，不上传或自动训练。报告、草稿和可选研究反馈独立存储。清空个人记录不影响婚恋记录，清空婚恋历史不删除个人记录与研究反馈。

支持个人报告、草稿、婚恋报告、全部本地记录 JSON 及研究反馈 CSV 导出。存储失败时显示提示，内存回答和报告仍可导出。相同范围、版本和回答的个人报告不重复新增；历史快照保留当时名称、解释和回答。

| 内容 | 当前版本 |
|---|---|
| 个人题库 | `rct-exploration-2026-11-23-v2` |
| 个人主型 | `rct-personal-types-v2` |
| 个人解释 | `rct-personal-explanation-v3` |
| 婚恋测评 | `rct-scenes-2026-11-23-v6` |
| 婚恋解释 | `rct-romance-explanation-v3` |

已知个人 v1 草稿保留有效原题回答和跳过，追加题保持未答；未知版本继续保护并支持导出。同一代码应结合规则版本理解，旧版 14 型名称和 8 种生活风格不重新解释为当前分类。不同场景或规则的历史不合并评价重复性。

详细依据见 [分类依据与命名](docs/分类依据与命名.md)。原始 48 项覆盖和新增观察题映射见 [内容覆盖表](RCT-48项内容覆盖.md)。其他设计包是历史方案，以本版文档与当前代码为准。

## 5. 开发与验证

HTML、CSS、原生 JavaScript，无构建步骤。

```bash
python3 -m http.server 8090
node --test tests/contracts.cjs tests/exploration-contracts.cjs tests/results-contracts.cjs
node tests/browser.cjs
node tests/exploration-browser.cjs
node tests/results-browser.cjs
node tests/structure-browser.cjs
```

浏览器回归需要 Playwright 与已安装的 Chrome；使用 `RCT_URL` 指定预览地址，`RCT_ARTIFACT_DIR` 指定截图和导出输出目录。测试覆盖类型可达、规则分离、覆盖不足、中点、旧草稿迁移、真实按钮答题、快照、导出、存储失败和手机展示。程序测试数据不作为真人研究样本。

当前实现文件：`js/exploration/banks/main.js` 追加中性方向题，`types.js` 定义主型，`profile.js` 保留特征解释，`model.js` 管理迁移与快照；`js/banks/love.js` 保留原题并追加模式题，`scoring.js` 分开计分，`report.js` 保存来源与依据，两个 `app.js` 负责对应报告展示。
